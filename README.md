# Client-Side AES-256-GCM Crypto Tool

ブラウザ標準の **Web Crypto API** のみを利用した、完全静的な AES-256-GCM 暗号化・復号ツールです。
サーバー処理、外部通信、トラッキング、永続化ストレージ（localStorage/Cookie等）を一切使用せず、プライベートなパスワードや機密情報を安全に暗号化して保存するために設計されています。

---

## 1. 仕組み

本ツールは純粋なクライアントサイド（ブラウザ内）で以下のように動作します。

```text
[ Master Key (文字列) ]
       │
       ▼ (UTF-8 Encode)
[ UTF-8 バイト列 ]
       │
       ▼ (SHA-256 ハッシュ化: 256bit)
[ AES-256 共通鍵 ]
       │
       ├─────────────────────────┐
       ▼                         ▼
[ 暗号化処理 (AES-GCM) ]   [ 復号処理 (AES-GCM) ]
   - 12byte ランダム IV       - IV 抽出
   - Plain Text 入力          - Ciphertext 抽出
   - 128bit 認証タグ付与      - 整合性検証 & 平文復元
```

### 暗号化出力フォーマット

暗号化結果はコピペや管理がしやすい1行文字列フォーマットを採用しています。

```text
AESGCM:v1:<base64(iv)>:<base64(ciphertext)>
```

- `AESGCM`: アルゴリズム識別子
- `v1`: フォーマットのバージョン
- `<base64(iv)>`: 暗号化ごとにランダム生成された 12 バイト（96bit）の IV（Base64 形式）
- `<base64(ciphertext)>`: 暗号文本体 + 128bit の GCM 認証タグ（Base64 形式）

---

## 2. AES-256-GCM について

本ツールでは **AES-256-GCM (Galois/Counter Mode)** を採用しています。

- **AEAD (Authenticated Encryption with Associated Data)**:
  暗号化だけでなく、「メッセージの改ざん検知（認証）」を同時に行います。
- **改ざん耐性**:
  暗号文や IV が 1 ビットでも書き換えられた場合、復号処理時に認証タグの検証が失敗し、即座にエラーとなります。
- **最高峰のセキュリティ**:
  現代の通信プロトコル（TLS 1.3 など）でも標準採用されている業界標準の暗号化方式です。

---

## 3. IV (Initialization Vector: 初期化ベクトル) について

- **長さ**: 12 バイト（96 ビット）固定（AES-GCM における推奨値）。
- **毎回ランダム生成**:
  暗号化を実行するたびに `crypto.getRandomValues(new Uint8Array(12))` を使用して暗号学的に安全な擬似乱数から新規生成します。
- **再利用厳禁**:
  同じ鍵で同じ IV を使って異なるデータを暗号化すると、AES-GCM では重大なセキュリティ脆弱性（鍵ストリームの漏洩）が発生します。そのため、毎回ユニークな IV を必ず生成します。
- **秘密情報ではない**:
  IV は秘密鍵ではないため、第三者に知られても安全です。復号に必要となるため、暗号データの一部として一緒に保持します。

---

## 4. セキュリティ上の注意点

1. **マスターキーの強度**
   - 鍵の導出には SHA-256 を使用しています。辞書攻撃や総当たり攻撃を防ぐため、十分な長さと複雑さ（大文字・小文字・記号・数字を含む16文字以上を推奨）を持つマスターキーを使用してください。
2. **ストレージ非保持ポリシー**
   - 本ツールは `localStorage`, `sessionStorage`, `IndexedDB`, `Cookie` への書き込みを一切行いません。
   - ブラウザを閉じるかリロードすると、入力した平文やマスターキーはメモリ上から破棄されます。暗号化した結果は必ずご自身でテキストファイルやメモ帳等に退避してください。
3. **ショルダーハック対策**
   - マスターキーの入力欄はデフォルトで伏せ字（`password`）になっています。入力内容を確認する際は周囲にご注意ください。
4. **Content Security Policy (CSP)**
   - HTML 内に厳格な CSP (`default-src 'none'; style-src 'self' 'unsafe-inline'; script-src 'self';`) を設定しており、万が一の外部通信やインジェクション攻撃を遮断しています。
